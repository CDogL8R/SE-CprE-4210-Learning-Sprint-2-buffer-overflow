Core Concepts & Architectural Reference Guide

Understanding x86 memory layout, call stack anatomy, vulnerable C functions, and defense engineering.

1. Call Stack Anatomy

When a C function is called, a contiguous region of memory called a Stack Frame is created. In x86 architecture, the stack grows downwards toward lower memory addresses, but arrays write upwards toward higher addresses.

  • Return Address (EIP/RIP): Stores where control returns after function completion.
  • Saved Frame Pointer (EBP/RBP): Holds the base pointer of the caller's stack frame.
  • Local Variables: Allocated below saved registers on the stack.
2. Why strcpy() is Vulnerable

Functions like strcpy(dest, src) copy characters until a null terminator ('\0') is encountered. They do not verify whether the destination buffer has sufficient capacity.

Unsafe: strcpy(), gets(), sprintf(), strcat()
Safe: strncpy(), fgets(), snprintf(), strlcat()
3. Control Flow Hijacking

When input exceeds the allocated buffer, excess bytes spill over adjacent local variables, saved EBP, and eventually overwrite the Return Address (EIP). When the function finishes with ret, the CPU pops the overwritten address into EIP, jumping to attacker-chosen instructions.

4. Compiler Protections
  • Stack Canaries (StackGuard): Places a secret random value right before saved EBP. Before returning, the function verifies canary integrity. If corrupted, it terminates immediately via __stack_chk_fail().
  • ASLR (Address Space Layout Randomization): Randomizes stack, heap, and library memory locations on each execution.
  • NX / DEP (No-Execute / Data Execution Prevention): Marks stack pages as non-executable to prevent shellcode execution.
